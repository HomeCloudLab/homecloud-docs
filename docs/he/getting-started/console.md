# שימוש בקונסול

הקונסול הוא ממשק המשתמש העיקרי ליצירת משאבים, הזמנת אנשים ובדיקת סטטוס. העמוד הזה הוא מפה של מה שתראו אחרי התחברות.

## פריסה

| אזור | מה הוא עושה |
|------|-------------|
| **סרגל עליון** | מחליף חשבונות, תפריט משתמש, שפה, עזרה |
| **סרגל צד שמאלי** | רשימת שירותים (Storage, Queues, Databases, Functions, …) ומרכז Account |
| **חלון ראשי** | דפי רשימה ולשוניות פרטי משאב |
| **כותרת תחתונה לסטטוס** | בקרת נתיב (ריחוף/לחיצה לנתיב המלא), פעמון התראות (מספר אדום של ממתינות), ופעילות ברקע (העלאות, העתקה/העברה ב-SO) |
| **מידע (ⓘ)** | עזרה הקשרית לדף או ללשונית הנוכחיים |

רוב השירותים עוקבים אחרי אותו דפוס:

1. **רשימה** — יצירה, חיפוש, פתיחת משאב.  
2. **פרטים** — לשוניות לסקירה, הגדרות, לוגים, דוגמאות API וכו'.

## התראות

פעמון הכותרת התחתונה הוא מרכז, לא תיבת דואר שנייה:

- **התג** (מספר אדום על הפעמון, בלי ללחוץ) = פריטים ממתינים: הקצאה/השלמה, חשבוניות, דיוני משימה שלא נראו, ומייל לא נקרא (אחד אם יש מייל).
- **Mail** — שורה אחת לכל תיבה (ספירה בלבד) → תיבת הדואר הזו.
- **Tasks** — שורה אחת לכל דיון שלא נראה → הפריט (`?focus=discussion`). יצירה / הקצאה / סיום גם כותבים אירוע דק לכל נמען.
- **הכל** פותח `/console/notifications` (ממתינים + אירועים שנראו לאחרונה). החלון הצף נשאר תצוגה קצרה של שלא נקראו.

הממשק מרענן ספירות רק כש-Realtime Gateway מסמן שינוי רלוונטי (עם debounce). תגובות והודעות מייל לא מועתקות לטבלת התראות.

השער הוא **ברמת חשבון**, לא רק Mail. חברים מתחברים אם יש להם לפחות הרשאת-קריאה אחת למשפחת אירועים (`tasks.read`, `iam.read`, `resources.read`, `billing.read`, `compute.read`, …). הם מקבלים רק אירועים של משפחות שהם מורשים לקרוא. **403** מהזרם הוא סופי — הקונסול לא מנסה שוב. חסר `resources.read` לא מסתיר את משימות או את הפעמון.

הקונסול שומר **חיבור SSE אחד לכל טאב**. משימות, Compute, מייל ופעמון ההתראות נרשמים לפילטרים על אותו זרם; כניסה לשירות לא פותחת בקשת `/realtime/events` נוספת. REST נשאר מקור האמת. אחרי דיפלוי הלקוחות מתחברים מחדש עם jitter כדי לא לפגוע ב-API באותה שנייה.

## קטלוג שירותים

פתחו **Services** בסרגל הצד (או `/console/services`) לקטלוג המלא עם תיאורים קצרים. שירותים מופעלים פותחים את דפי הקונסול שלהם; פריטים שמסומנים כ-coming soon עדיין לא לחיצים.

## איפה למצוא משימות נפוצות

| משימה | לכו אל |
|-------|--------|
| העלאת קבצים / אתר סטטי | **Object Storage (SO)** → bucket → Objects |
| יצירת תור ובדיקת DLQ | **Queues (MQ)** |
| הקצאת PostgreSQL / MySQL / MongoDB | **Databases (MDB)** |
| יצירת מטמון Redis | **Redis** |
| עריכה ופריסה של קוד serverless | **Functions** |
| פריסה מתבנית | **Applications** |
| עיון ב-pods / הגדלת deployments | **Kubernetes** |
| `docker push` לתמונות פרטיות | **Registry (IR)** |
| קריאה ושליחת דוא״ל | **Mail** |
| אחסון טוקני API לאפליקציות | **Secrets** |
| תפקידים, מדיניות, Access Keys | **IAM** |
| הבאת דומיין משלכם | **Account → Domains** (או **Domains** בקטלוג) |
| צפייה בתעודות TLS | **SSL** |
| הזמנת חברים, יומן ביקורת, פרויקטים | מרכז **Account** |
| התראות ממתינות | פעמון בכותרת התחתונה → **הכל** (`/console/notifications`) |

## מרכז Account

תחת **Account** מנהלים את ה-tenant עצמו:

- **Overview** — סיכום החשבון  
- **Security / sessions** — סיסמה, MFA, סשנים פעילים  
- **Members** — הזמנה ותפקידים  
- **IAM users** — משתמשי קונסול לחשבון  
- **Access keys** — אישורי data-plane (גם תחת IAM)  
- **Audit** — מי עשה מה  
- **Projects** — קיבוץ אפליקציות ומשאבים  
- **Resources** — מלאי חוצה־שירותים  

פרטים: [חשבון וצוות](../guides/account.md).

## עזרה בתוך המוצר

לכל דף מרכזי ולרבות מהלשוניות יש כפתור **Info**. הוא פותח פאנל קצר למסך הזה. התיעוד הזה מעמיק יותר (זרימות מלאות, CLI ודוגמאות SDK). השתמשו בשניהם: Info ל«מה המסך הזה?», התיעוד ל«איך מאוטמטים את זה?».

## טיפים שחוסכים זמן

- העתיקו **`so://bucket/key`** מלשונית Properties של אובייקט כשמשתמשים ב-CLI — ציטטו ב-PowerShell אם המפתח מכיל רווחים.  
- מחרוזות חיבור וסיסמאות למסדי נתונים נמצאות בלשונית **Connection** של המופע (חשיפה מתועדת בביקורת).  
- העלאות ארוכות מציגות התקדמות ב**כותרת התחתונה**, לא רק כ-toast — אפשר למזער ולהמשיך לעבוד.  
- אם פעולת יצירה נכשלת עם שגיאת מכסה, בדקו מכסות ב-**Account** או פנו לאדמין פלטפורמה.
