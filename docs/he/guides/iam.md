# IAM

IAM שולט **מי יכול לעשות מה** בחשבון: זהויות קונסול (משתמשים + קבוצות + מדיניות), Roles/Policies של data-plane, ו-Access Keys ל-CLI/SDK/Terraform.

| פריט | ערך |
|------|--------|
| Console | **IAM → משתמשים** (יצירה / עריכה) · **חשבון → משתמשים** (תצוגה לקריאה בלבד) |

## שתי שכבות (אל תערבבו אותן)

### 1. גישת קונסול (אנשים) — קבוצות ומדיניות (ADR-053)

אנשים מקבלים הרשאות מ**צירופי מדיניות** ומ**חברות בקבוצות**, לא ממטריצת ארבעה תפקידים. עמודת הגישה בקונסול מציגה את הצירופים האמיתיים. `account_role` נשאר ב-API לתאימות ולא משמש לתצוגה.

ארבע קבוצות המערכת עדיין קיימות וניתן לשייך אותן כמו כל קבוצה:

| קבוצת מערכת | שימוש טיפוסי |
|-------------|---------------|
| `AccountOwners` | ניהול מלא של החשבון |
| `AccountAdmins` | חבילת מנהל |
| `Builders` | בנייה / הפעלת עומסים |
| `Readers` | קריאה בלבד |

קבוצות ומדיניות מותאמות חיים תחת **IAM → Groups / Policies**. הערכה: **Deny > Allow > Deny מרומז**. הענקה לאחרים דורשת **CanDelegate**.

יוצרים משתמשים תחת **IAM → משתמשים** (הזמנה במייל או שם משתמש/סיסמה). הרשאות ביצירה אופציונליות — משתמש בלי שיוך מתחבר אבל אין לו גישה עד שמשיכים לו קבוצה או מדיניות. לדיבאג השתמשו ב-**IAM → אבחון**: קודם הסימולטור, ואז כרטיסי גישה אפקטיבית לפי שירות.

הבילדר הוויזואלי צובר statements בין שירותים (לא מחליף את המסמך בהחלפת שירות). פתיחת מדיניות לא משנה אותה; מעבר Visual ↔ JSON לא יוצר מסמך חדש.

### קטלוג workspace

הקונסול מציג שירותים מ-`GET /api/v1/accounts/{id}/catalog` (קטלוג ששוחרר ∩ IAM). מוצרים שלא שוחררו מושמטים. שירות ששוחרר אבל לא הוענק נפתח כ-workspace ריק.

### 2. IAM של data-plane (אוטומציה)

| אובייקט | מטרה |
|---------|------|
| **Policies** | מסמכי `service:Action` + ARN (`Deny` גובר על `Allow`) |
| **Roles** | זהויות שניתן להניח (Functions משתמשות ב-Role ARN כ-`execution_role`) |
| **Access Keys** | אישורים ארוכי־חיים למשתמש; ההרשאות ממדיניות/קבוצות |

מזהי חשבון ב-ARN הם **מספר החשבון בן 12 ספרות**.

## Access Keys (credentials-first)

יצירה וביטול תחת **IAM → Access Keys**. מדריך מלא: [Access Keys](../getting-started/access-keys.md).

מפתחות משתמש יכולים לקרוא ל-APIs **ניהוליים** (רשימת buckets, תורים, …) ב-SigV1 כשהמדיניות Allow — בלי JWT של קונסול. `homecloud login` לדפדפן ול-step-up נדיר. ראו [אימות CLI](../cli/authentication.md) ו-[ארכיטקטורת אימות](authentication-architecture.md).

Roles יכולים גם לסמוך על **GitHub Actions OIDC**. Terraform אז משתמש ב-`HC_ROLE_ARN` במקום מפתח ארוך־חיים. ראו [Terraform — GitHub OIDC](../terraform/index.md#github-oidc-no-long-lived-key).

## מדיניות

1. פתחו **Policies** → צרו או שכפלו starter מנוהל.  
2. צרפו את המדיניות למשתמש, קבוצה או Role.

## Roles ו-Functions

Functions חייבות להשתמש ב-**Role ARN** (לא בשם Access Key).

## אבחון

פתחו **IAM → אבחון**.

1. **סימולטור** (למעלה) — האם `service:Action` מותר על ARN בלי לבצע את הפעולה.
2. **גישה אפקטיבית** (מתחת) — כרטיסים לפי שירות עם תגיות קריאה / כתיבה / יצירה. לחיצה על תג או `+N` מציגה את שמות הפעולות המדויקות.

הסימולטור עונה על השאלה שבשמה הגעתם. הכרטיסים מסכמים מה משויך אחרי ש-Deny גובר.
